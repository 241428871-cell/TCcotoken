# TCcotoken

把本机 Codex token 记录与同一账号的官方额度变化对齐，报告本机用量、尚未解释的额度，以及在明确假设下的非本机折算值。非本机包括其他设备和云端，无法仅由差值区分设备。

## 数据读取

- 优先调用可用的 `get_usage_limits` 工具。按 `rateLimitsByLimitId` 选择对应额度桶，缺失时才使用 `rateLimits`。记录采集时间、账号、计划、limit_id、usedPercent、windowDurationMins、resetsAt；缺失字段不视为零。不同模型的独立额度桶分别处理。
- `usedPercent` 是已用百分比，剩余为 `100 - usedPercent`。五小时与周窗口不能混用。
- 选择用户所需窗口；周期起点可按 `resetsAt - windowDurationMins * 60` 推算，但应结合历史快照验证它是否适用于当前窗口。额度重置、兑换重置信用或计划变化必须分段。
- 读取实际 `CODEX_HOME` 下的 `sessions` 与 `archived_sessions`；未设置时通常是 `~/.codex`。如用户指定 CodexBar 数据源，先检查其覆盖范围与原始口径，不假定其显示的是账号总 token。
- 本任务只需 token_count、turn_context、session_meta 等元数据。不要输出对话正文、认证文件、密钥或完整账号标识。
- 确认记录归属当前账号及本机；账号切换、导入会话或同步记录无法归属时单列为未知来源。保留统计覆盖范围与缺漏说明。

## 本机 token 统计

读取 JSONL 中 `event_msg` / `payload.type = token_count`：

- `info.total_token_usage` 为会话累计计数，不能逐行相加。
- 第一条有效记录一般采用 `last_token_usage`，不直接加入首次累计值，以免把 fork 继承的历史当成新消耗。已有前序日志可验证时，以实际累计增量为准。首次累计远大于 last 时，记录可能遗漏的历史用量，不声称全量精确。
- 后续累计增长取相邻累计差；累计完全相同跳过。计数下降或重置时，采用可验证的 last 增量并另起计数段，不用逐字段截零掩盖异常。
- info 为空时仍可读取额度快照，不沿用上次 last 再计一次。
- 先用窗口外最近计数作为基线，再将窗口内增量按事件时间归入时段。跨窗口请求的精确归属无法确定时披露边界误差。
- 排除 sessions/archived_sessions 的重复副本和 fork 复制历史。结合会话标识、复制前缀、时间戳、累计与 last 计数识别；时间戳相同不足以判定重复。无法消歧的量单列。
- 用 `turn_context.model` 对增量归属模型；未知模型单列。采集后固定截止时间，让额度读数和 token 汇总尽量接近同一时刻。

汇总 `input_tokens`、`cached_input_tokens`、`output_tokens`、`total_tokens`；核对字段一致性。通常 cached 是 input 的子集、reasoning_output 是 output 的子集，两者都不能再加到 total。存在 cache_write 字段时先核实当前日志语义，再决定如何计权。

把普通模型与 `codex-auto-review` 等特殊来源分别列出。没有证据确认特殊来源是否消耗同一额度时，不默认免费、不直接把其差值归为其他设备；需要提供包含/排除的情景或标为尚未解释。

## 官方口径与加权

优先检查当前官方文档： https://learn.chatgpt.com/docs/pricing 或 https://developers.openai.com/codex/pricing 。查证模型、普通/快速模式、输入/缓存/输出 credit 比例，以及是否适用于用户计划。不要把历史费率写成永久常量。

若账号提供同时间窗、同覆盖范围的完整 token 总数，可直接计算：

`非本机 token = 账号总 token - 本机 token`

若只提供额度百分比，则不能直接换算原始 token；使用下面的经验估计。官方 credit 费率只能作为权重代理，不能声称等同订阅额度扣减公式。

对已知模型 m，用当前官方费率作为相对权重：

`W_m = 非缓存输入 * a_m + 缓存输入 * b_m + 输出 * c_m`

`W_local = sum(W_m)`

费率单位保持一致，可归一化到一个参考模型的输入费率。快速模式等倍率只在得到证据确认时应用。未知模型/特殊来源不擅自套用参考模型；其影响进入不确定性说明或独立情景。

## 时段标定及估算

1. 从日志中的 `rate_limits` 提取同 limit_id、窗口长度和 resetsAt 的历史点，按时间排序。并发返回会有延迟、整数百分比和短暂回退；不得把每次正向跳动累加为总消耗。使用边界附近的一致快照或稳健汇总，并披露滞后。
2. 优先选择已知仅本机使用、模型构成相似的较长时段，且额度增长足够大，减小百分比取整误差。选择多个候选段用于敏感性分析。
3. 如果没有仅本机使用证据，可使用本机活跃时段作为条件标定，但明确其可能包含非本机消耗；这会污染标定系数，无法可靠确认非本机比例。
4. 将 token 增量和额度快照严格对齐到标定区间 A：

`k_A = W_local,A / (U_end,A - U_start,A)`

其中 U 为已用百分比数值，差值单位是“百分点”，k 表示每个百分点的加权用量。没有额度增长的时段不能独立标定。

5. 对目标区间 B，令 `DeltaU_B = U_end,B - U_start,B`：

`本机额度估计 L_B = W_local,B / k_A`

`未解释额度 R_B = DeltaU_B - L_B`

`本机占已消耗额度 = L_B / DeltaU_B * 100%`

`未解释部分占已消耗额度 = R_B / DeltaU_B * 100%`

完整周期且起点为零时，DeltaU_B 可用截止时官方已用百分比；任意子区间不能用截止时累计百分比代替增量。

6. 只有归属和计费覆盖足够清楚，才把 R_B 称为非本机估计。否则报告“未解释部分（可能含其他设备、云端及特殊来源）”。负残差或本机估计超过总消耗说明标定失效，不静默截零形成确定比例。
7. 如需原始 token 折算，使用标定段的加权/原始 token 比：

`非本机折算 token = R_B * k_A * (T_local,A / W_local,A)`

明确这是“按本机标定时段模型与缓存构成折算”，并非远端实际 token。
8. 换用多个合理标定时段和特殊来源计费情景重复计算。所得最小/最大值称敏感性范围，不称置信区间；必要时说明仍可能接近零，或数据不足以辨识。

## 输出

先给比例及可信度，再用简表列出：

- 时间范围、账号额度桶与已用/剩余额度。
- 本机普通模型原始 token、缓存比例、特殊/未知来源 token。
- 本机和非本机或未解释部分各占已消耗额度的比例。
- 各占整个周期总额度的百分点，避免把两个分母混淆。
- 标定时段、代理权重来源、敏感性范围与主要不确定性。

合成演示：假设周期已用 50%，条件估计本机用 40 个百分点、剩余未解释 10 个百分点，则在已消耗额度中本机约 80%、未解释约 20%，比例约 4:1，周期剩余 50%。这些是演示数字，不对应任何真实账号，不可在实际任务中复用为固定结论。

没有完整日志、可信标定或官方全量 token 时，仍报告能核实的本机统计与官方额度；对无法确定的归属给出条件估计或说明不可辨识，不填造比例。
